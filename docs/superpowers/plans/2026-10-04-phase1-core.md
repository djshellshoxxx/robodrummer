# RoboDrummer Phase 1 Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish a portable, testable C++ core for RoboDrummer before JUCE/plugin plumbing, covering musical time, drum events, style parameters, deterministic groove generation, MIDI intervention commands, and scheduling.

**Architecture:** Keep the first core library independent of JUCE so timing/groove logic can be unit-tested with a normal C++ compiler. JUCE will wrap this core in the VST3/standalone layers in the next phase. All realtime-facing data structures use fixed-size/value types and avoid ownership or allocation inside per-block scheduling paths.

**Tech Stack:** C++20, CMake 3.22+, CTest. JUCE is intentionally deferred to the plugin wrapper task after the core contracts are proven.

**Spec:** `SPEC.md`

## Global Constraints

- Primary initial platform: Windows x64.
- Initial plugin target: VST3; standalone built alongside it; CLAP follows after the core engine stabilizes.
- The audio thread must not perform disk I/O, blocking operations, network operations, or uncontrolled allocation.
- The initial product supports one live guitar analysis source only.
- Stability and graceful recovery take priority over excessive responsiveness.
- MIDI is optional intervention, not a prerequisite for autonomous operation.

## Review Focus

1. Invalid tempo values must never produce divide-by-zero or negative beat durations.
2. Event generation at the end of a bar must not schedule events beyond the bar unless explicitly requested.
3. Deterministic generation with the same seed/context must return identical events.
4. MIDI commands outside the known command enum must not mutate musical state.
5. Scheduler ordering must remain stable for events sharing the same sample offset.

## Phase 1 Completion Contract

Phase 1 is complete when the portable core builds without JUCE, all core tests pass, deterministic groove generation is demonstrated, and CI is configured to run the same tests on Windows and Linux. The next plan will add the JUCE VST3/standalone wrapper and connect host audio/MIDI to these contracts before implementing guitar-follow analysis.
